Elevance and Healthy Blue provider sites · Author reference

Site author guide

Build and maintain provider pages in Document Authoring (DA). This guide explains page setup, shared navigation and footer content, reusable sections, and all 34 block implementations in this repository.

Detailed examples use the Healthy Blue North Carolina site, adobedrago/elevance-nc. The elevance site shares the code but uses its own DA content and default theme. Open its DA content browser for that site. NC-specific layouts require theme: north-carolina; they are not a design catalog for the other site.

Reference date: October 15, 2026. Block behavior follows the current repository implementation. Page examples and usage counts come from the NC preview index at the time of documentation. Code availability, editor-picker availability, and production readiness are separate things.

Set up and edit a page

  1. Open the correct DA site. For NC, use the NC content browser. Work in /north-carolina-provider/ for provider pages.
  2. Duplicate an approved page with a similar purpose, or create a document at the intended path. Use lower-case words separated by hyphens. A path is the page’s URL, so coordinate redirects before renaming an existing page.
  3. Keep one H1 for the page title. Use H2 for main sections and H3 for subsections. Write ordinary text, lists, images, and links as normal content; use blocks when a specific layout or interaction is needed.
  4. Keep or add the page Metadata table shown below. Replace the example title and description. Use the actual image asset or image URL for social sharing.
  5. Preview, check the page at desktop and mobile sizes, then follow the publishing checklist. Review shared fragments separately when you change them.

The visible H1 and the metadata title serve different purposes; update both when appropriate. robots: noindex excludes a page from this site’s search when the index record contains it. Coordinate publication and indexing if the page must be kept out of search results.

Block names and variants

A block is authored as a table. Its first, merged row names the block; the following rows hold content. This guide shows that merged row in each example. Instructions such as “Image,” “H2,” “Bulleted list,” and “Link” describe what to insert in DA; replace them with real images, formatting, lists, and hyperlinks. They are not literal content to publish.

Use the exact block name shown, such as hero-banner or cards-featured. A custom block is its own implementation; do not rewrite hero-banner as Hero (banner). Parenthesized options are only for supported variants of a base block, such as Table (striped, bordered) or Video (autoplay).

The checked-in editor definitions mainly register starter blocks. Custom NC blocks may not appear in a picker or Library. Copy an existing working instance with the same structure, or coordinate editor registration with a developer. Do not assume a block is unavailable just because it is missing from the picker.

Shared header and navigation

Every normal page loads a header automatically. Its nav metadata selects the navigation fragment; NC pages use /fragments/nav. Edit the NC navigation document to change the logo, navigation labels, destinations, or utility links across pages that use it.

3. Tools Separate paragraphs with Log in and Members hyperlinks. Utility links beside generated text-size and search controls.

Build the hierarchy with real nested lists and indentation in DA. Keep top-level menu labels as plain paragraph text when they open a submenu. Retain the section breaks; adding an introductory section shifts how the header interprets all three sections. The current top-level NC labels are Resources, Claims, Patient Care, Eligibility & Pharmacy, Communications, and Our Network.

Desktop menus open on hover or activation. Below the NC desktop breakpoint, a menu button controls navigation and search; the mobile header can hide while scrolling down and reappear while scrolling up. Search and the A/A/A text-size controls are generated by code. Do not author copies in the fragment.

Other site and fragment defaults

The header reads the current page’s nav value, falling back to /nav when it is absent. The footer reads footer, falling back to /footer. Both first request the site-root fragment, then a local /content path, then the legacy local default. These fallback paths are loader behavior, not additional fragments authors should insert. Keep each site’s approved metadata and fragment structure; do not apply NC theme metadata to the other site by default.

Breadcrumbs

Set breadcrumbs: true on an interior page to enable breadcrumbs. The trail is derived from the navigation tree and the current URL, with a Home link first. If a page is missing from the tree, its metadata title is used as a fallback. Check the result after changing navigation nesting or page paths.

A header fragment edit affects every page referencing that path. Preview the fragment and a representative page before publishing. Do not insert the fragment or a Header block again in the page body.

Shared footer

Every normal page also loads a footer automatically. NC pages select /fragments/footer through metadata. Edit the NC footer document for site-wide legal statements and utility links.

Keep two sections in authored order: first, paragraphs of links; second, legal copy and the copyright paragraph. On NC the renderer displays the legal section first, followed by the links. Do not reverse the authored order to match the preview.

  • Link section: Healthy Blue member website, Contact Us, Privacy Policy, Waste, Fraud and Abuse, Terms of Use, and Download Adobe Reader.
  • Legal section: approved plan/license text and copyright. The copyright year is authored text; it is not automatically replaced by the current year.
  • The Adobe Reader link to https://get.adobe.com/reader/ becomes the Reader badge automatically on NC.

Keep legal changes with the appropriate content approver. The CTA Footer Banner block is a separate page-body component and does not replace the global footer. A duplicate footer or header in DA can be a page-loader issue; first check that the page body does not contain extra copies, then report the page URL and preview behavior to a developer.

Shared content and formatting

Sections and reusable content

Use DA section breaks to separate page bands. Section Metadata affects its own section; page Metadata affects the page. A Fragment block includes a separate DA document and makes changes reusable across all consuming pages.

Example section metadata, placed in the section it styles
Section Metadata
Style light

light and highlight are supported section background styles. Keep existing approved section styles when duplicating a page. On NC, a light section beginning with H3 also has a specific callout treatment, so heading structure can change its appearance.

Links and buttons

Authoring on NC Result
Normal hyperlink in prose or its own paragraph Text link.
A bold hyperlink alone in a paragraph Primary button.
An italic hyperlink alone in a paragraph Secondary button.

Keep a button link alone in its paragraph, with no extra words around it. Some blocks apply their own link treatment: CTA Footer Banner creates its button automatically; Accordion Doc Links can force text links or standalone buttons; Cards Featured uses text-and-chevron styling. The default-site decorator can turn an ordinary standalone link into a button, so check the intended site.

Use site-relative URLs such as /north-carolina-provider/forms for internal destinations. Use descriptive labels for PDFs, including file type and useful context. On NC, external HTTP/HTTPS links normally open a “You’re leaving our site” confirmation; continuing opens a new tab. Download links bypass that confirmation. Email, telephone, and same-origin links do not use it.

Images and accessibility

Insert actual image assets, not filenames typed in cells. Supply meaningful alt text for informative images and appropriate empty alt text for decorative images. Keep each image alone in its cell when the model calls for an image-only cell. Preview crops and mobile stacking; avoid embedding essential text in an image. Use real lists for lists, descriptive link text, and headings in a logical order.

Review and publish

  1. Check the page path, one H1, metadata title/description, and NC theme/nav/footer metadata.
  2. Confirm block names and cell counts. Replace every instructional placeholder with real content. Check that extra rows have not hidden or discarded text.
  3. Preview desktop and mobile. Check image crops, heading order, buttons, lists, long document titles, and column reading order.
  4. Test destination links, document availability, navigation menus, accordions, tabs, and any service blocks used on the page. A working sample response is not proof that a production service is connected.
  5. For a shared fragment change, review the fragment and at least a home and interior page. Preview/publish the fragment itself as well as affected pages according to your team’s release workflow.
  6. Use the preview and publish actions available to your DA account or Sidekick. Saving content is not the same as publishing it. Confirm the result on the preview host, then the live host after publishing.
  7. If pages or PDFs should appear in search, verify index visibility after release. Ask the developer to refresh the document/suggestion assets when needed.

NC preview: preview home. NC live: live home. Repository code releases are separate from DA content publication.

Maintenance and technical reference

Content authors maintain page copy, links, images, metadata, and shared DA fragments. Developers maintain block implementations, theme styling, editor registration, generated search assets, hardcoded dialogs, and service integrations.

The site uses one code repository for multiple DA sites. NC styling is scoped by the theme body class; do not copy the NC theme to another site unless that design is intended. There is intentionally no single fstab mount. Content is authored in DA. Any regenerated local migration content must come from the importer; do not hand-edit or delete imported content files.

The default local NC preview runs on port 3000. Override the port locally if needed. Start it with aem up --port 3000 --url https://main--elevance-nc--adobedrago.aem.page --no-stop-other --no-open from the repository, then open http://localhost:3000/north-carolina-provider/home. Local repository code and the deployed main branch may differ.

After committing and pushing the documentation, wait for Code Sync to deploy it, then open /docs/author-guide.html on the preview or live site host. Use the .html extension: extensionless paths resolve through DA content. Commit the guide HTML, CSS, JavaScript, and its screenshot assets together.
